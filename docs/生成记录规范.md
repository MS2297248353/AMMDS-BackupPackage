# 生成记录规范（`work/records/` 与 `work/images/` 的组织方式）

> **读者**：AI 编码助手（`Rule/AI备份包生成规范.md` 的配套说明）。
> **作用**：定义「抓取/转换」与「打包」之间的**中间契约**。字段级格式一律以 `Rule/` 那份规范为准，
> 本文件只回答一个问题：**中间产物放在哪、长什么样、怎么和图片对齐。**
> **谁读它**：写抓取脚本与转换脚本的 AI。用户不需要读。

---

## 1. 目录与文件命名（硬约定）

```
work/
├── _meta.json                    # 机器配置：package_type / source_mode / image_strategy / ...
├── source/                       # 原始留痕：只读证据，不参与打包
│   ├── <site>-notes.md           # 侦察笔记：DOM 结构 / JSON 字段路径 / 需要登录与否
│   ├── <site>-<type>-<date>.raw.json
│   └── <site>-failed.txt
├── scripts/
│   ├── fetch_<site>.py           # 抓取：原始响应 -> source/
│   └── to_records.py             # 归一化：source/ -> records/ (+ images/)
├── records/
│   └── <type>.json               # 唯一参与打包的数据文件，顶层 JSON 数组
└── images/
    └── <ref>                     # 目录树 == ref 本身
```

- `records/` 里**只允许存在当前 `package_type` 对应的那一个数据文件**（多余的删掉，避免误打包）。
- `records/<type>.json` 顶层必须是数组；`{ "items": [...] }` 形式只用于 AMMDS 的单文件兼容模式，**zip 包禁用**。

---

## 2. `records/<type>.json` 最小骨架

每条记录都必须有**导入匹配键**，否则该条目在 AMMDS 里必然失败。

```jsonc
// movie.json —— 匹配键 uniqueid
[
  {
    "uniqueid": ["ABC-123"],            // ★ 数组，至少一个
    "originalTitle": "ABC-123 Sample",  // ★ 原始标题
    "titleCn": "示例影片",               // 可选
    "premiered": "2026-08-01",          // 可选，yyyy-MM-dd
    "runtime": 120,                     // 可选，整数（不是 120.0）
    "rating": 8.5,                      // 可选，数字
    "genre": ["剧情"], "tag": ["示例"],  // 可选，字符串数组
    "actors": [{"name": "示例演员", "role": "女优"}],
    "poster": ["data/images/media/2026/09/abc-123-poster.jpg"],  // 数组
    "dataSource": "user"
  }
]
```

```jsonc
// actor.json —— 匹配键 name
[
  {
    "name": "示例演员",                  // ★ 不可为空
    "aliases": ["别名"],
    "gender": "female",                 // male / female / shemale
    "heightCm": 160, "weightKg": 45.5,  // 数字
    "birthDate": "1995-01-02",
    "agency": ["示例经纪"],
    "poster": "data/images/actor/2026/09/x.jpg",  // 单值！
    "thumb": ["data/images/actor/2026/09/x-1.jpg"], // 数组
    "dataSource": "user"
  }
]
```

```jsonc
// comic.json —— 匹配键 title（有 isbn 优先按 isbn 匹配）
[
  {
    "title": "示例漫画",                 // ★
    "isbn": "9780000000001",            // 强烈建议填，且能让条目 key 变成可读的 ASCII
    "type": "comic",                    // comic / album
    "cover": "data/images/gallery/comic/cover/x.jpg",      // 单值
    "backCover": "data/images/gallery/comic/cover/x-b.jpg",
    "genre": "分类", "tags": ["标签"],
    "writer": "作者",
    "ageRating": "Adults Only 18+",     // 含空格，原样写
    "chapters": [                       // ★
      {
        "title": "第 1 话",
        "episode": 1,                   // 整数
        "pages": [                      // 按阅读顺序
          {"imagePath": "data/images/gallery/comic/story/x-001.jpg", "sequence": 1},
          {"imagePath": "data/images/gallery/comic/story/x-002.jpg", "sequence": 2}
        ]
      }
    ]
  }
]
```

```jsonc
// novel.json —— 匹配键 title
[
  {
    "title": "示例小说",                 // ★
    "author": "作者",
    "genre": "玄幻",                    // 单值
    "tags": ["标签"],
    "status": "serial",                 // finish / serial / draft / continue / writing
    "cover": "data/images/novel/cover/x.jpg",   // 单值
    "chapters": [                       // ★
      {"title": "第一章", "content": "正文一。\n正文二。", "sort": 1}
    ]
  }
]
```

> 完整字段表见 `Rule/AI备份包生成规范.md` 第 5 节。**不要写**派生字段（`comic.pageCount` /
> `episodeCount`）、**不要写**被忽略字段（`id` / `createdTime` / `updatedTime` / `version`）。

## 3. 类型正确的写法速查

| 类型 | 正确 | 会静默丢数据 |
| --- | --- | --- |
| 整数 | `"runtime": 120` | `120.0`（条目导入失败）、`"120"` |
| 数字 | `"rating": 8.5` | `"8.5"` |
| 日期 | `"premiered": "2026-08-01"` | `"2026/08/01"`、时间戳 |
| 布尔 | `"fullChapter": false` | `"false"` |
| 枚举 | `"gender": "female"` | `"女"`、`"Female"` |
| 缺失 | 直接省略该字段 | `"未知"` / `"-"` / `"N/A"` |

## 4. 图片：`work/images/` 与 `ref` 的对齐

### 4.1 `image_strategy = pack`

1. 在 `data.json` 的图片字段里写**引用键**（以 `data` 开头，扩展名必须是真实格式）：
   `"poster": ["data/images/media/2026/09/abc-123-poster.jpg"]`
2. 在 `work/images/` 下**用同一个字符串建目录树**并放文件：

   | `data.json` 里的值（= ref） | 本地文件位置 |
   | --- | --- |
   | `data/images/media/2026/09/abc-123-poster.jpg` | `work/images/data/images/media/2026/09/abc-123-poster.jpg` |
   | `data/images/gallery/comic/story/x-001.jpg` | `work/images/data/images/gallery/comic/story/x-001.jpg` |

3. 然后 `python tools/auto_backup.py build`。脚本用 `ref` 作 key 调用 `build_backup()`，
   自动完成 `imageFiles` 登记、`path` 生成（`images/<条目key>/<字段名>_<序号>.<ext>` 或
   `images/<条目key>/pages/page%05d.<ext>`）与 `sha256` 计算。**不要手写 `imageFiles`。**

约束（脚本会检查）：
- `pack` 策略下，每个非 `http(s)` 的图片字段值都必须在 `work/images/` 有对应文件，否则 `build` 中止并列出缺失清单。
- 同一个 `ref` 只放一个文件；跨字段/跨条目重复引用会自动只打包一次。
- 文件必须是**真实图片字节**（校验 magic number），扩展名与内容一致——否则前端破图。

### 4.2 `image_strategy = link`

图片字段写完整 URL，保留原大小写与 `%20` 等查询参数，**不要**放进 `work/images/`：

```json
"poster": ["https://img.example.com/a%20b.jpg?w=800"]
```

### 4.3 `image_strategy = none`

不写任何图片字段。（`build` 若发现仍残留引用会给出 WARN。）

### 4.4 混用

允许一部分字段走 `pack`、一部分走外链：外链写 `http(s)://` 值（`build` 自动忽略），
打包引用写 `data/...` 值（必须在 `work/images/` 有文件）。这也是「只打包封面、剧照外链」的推荐做法。

## 5. 条目 key 与包内路径（了解即可，脚本自动算）

- 条目 key 优先级：`isbn` → `title`（小说/漫画）/ `name`（演员）/ `originalTitle`（影视）。
- 安全化：非 `[a-zA-Z0-9_-]` 一律换成 `_`，去掉首尾下划线；全空则用 `item_<下标>`。
- **纯中文标识会整体变成下划线**，因此漫画/小说强烈建议填 `isbn` 或让标识含字母数字，
  这样包内目录可读（`images/9780000000001/pages/page00001.jpg` 而不是 `images/item_0/...`）。

## 6. `work/_meta.json` 字段说明

| 字段 | 说明 |
| --- | --- |
| `package_type` | `movie` / `actor` / `comic` / `novel`，决定 `manifest.type` 与读哪个 records 文件 |
| `source_mode` | `scrape`（AI 抓取） / `existing`（用户提供数据） |
| `image_strategy` | `pack` / `link` / `none` |
| `app_version` | 写入 `manifest.appVersion`，缺省 `1.6.80` |
| `conflict_policy` | 仅写入交付说明，供用户导入时选择：`skip` / `overwrite` / `merge` |
| `generated_at` | 首次归一化时间（ISO-8601） |
| `todo_snapshot.*` | 用户答案的**原样抄录**：`site` / `urls` / `scope` / `target_list` / `image_detail` / `extra` |
| `source.*` | `input_paths`（existing 模式的输入路径）、`entry_url`、`fetched_at`、`pages`、`notes` |
| `notes` | 你对本次产物的补充说明，会写进交付说明第 6 节 |

---

## 7. `work/build_config.json`（可选构建开关）

打包参数（type / 图片策略 / 版本号）一律以 `work/_meta.json` 为准；本文件只放构建行为开关：

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `run_verify` | `true` | 打包后是否跑《AI备份包生成规范》第 9 节结构自检。关掉只剩一条 WARN 提示，**不推荐** |
| `fail_on_warning` | `false` | 存在 WARN 即视为失败（等价命令行 `--strict`） |

文件缺失、解析失败或字段类型不对时，一律回退默认值并打印 WARN，不会中断构建。

---

## 8. 自检命令（每次改完 records / images 都跑）

```bash
python tools/auto_backup.py build --strict   # 打包 + 结构自检 + 质量自查，WARN 也算失败
python tools/auto_backup.py verify output/<zip>   # 只对已有 zip 跑规范第 9 节自检
python tools/auto_backup.py report                # 按 output/ 最新 zip 重写 deliver.md
python tools/auto_backup.py selftest              # 用内置 mock 数据自检整套框架
```

`build` 的质量自查覆盖规范第 11 节的高危项：缺匹配键、整数写成小数、占位符值、
被忽略字段、`comic`/`novel` 无 `chapters`、本地引用未打包、漫画页总量提示。

**退出码**：`0` 通过；`1` 自检发现问题；`2` 环境或输入缺失（缺 records、图片缺失、`_meta.json` 非法）。
